## Implemented

### 1. Explicit deterministic instance identity

For instance slug `<instance>`:

- Worker: `xingyu-beta-<instance>`
- D1: `xingyu-beta-<instance>-db`
- R2: `xingyu-beta-<instance>-media`
- runtime `APP_ENV=beta`
- runtime `INSTANCE_ID=beta:<instance>`

The same slug deterministically produces the same plan.

### 2. Production hard rejection

A1:

- rejects production-like instance slugs such as `prod`, `production`, `live`, `primary`, and `main`;
- verifies generated names are the deterministic `xingyu-beta-...` names;
- reads checked-in production Worker/D1/R2 identifiers and refuses exact collisions;
- rejects a resolved beta D1 database ID if it matches the checked-in production D1 ID;
- never uses the production Wrangler config for beta deployment.

### 3. Dry-run by default

`apply` and `decommission` do not mutate Cloudflare unless `--execute` is supplied.

`prepare` and dry-run `apply` generate/review the plan only. Generated artifacts live under ignored `site/outputs/beta/<instance>/`.

### 4. Reviewable non-secret manifest/config

The generated manifest/config contains:

- instance slug and `beta:<instance>`;
- deterministic Worker/D1/R2 names;
- resolved beta D1 ID after creation;
- binding names;
- required secret **names** only.

The generator does not accept secret values. The initial generated Worker config has:

- no production/custom route;
- `workers_dev=false`;
- `APP_ENV=beta`;
- `INSTANCE_ID=beta:<instance>`;
- `DB_SCHEMA_MODE=migration-only`.

### 5. A2 runtime + D1 identity prerequisite

A1 explicitly satisfies the A2 contract.

Before any remote `apply --execute`, the CLI verifies that A2's `db/instance-identity.ts` beta/INSTANCE_ID contract has been integrated. On the A1 owner branch alone this gate intentionally refuses remote provisioning; A6 must first integrate A2.

After schema preparation A1 explicitly establishes and then re-reads:

- `app_meta.app_environment=beta`;
- `app_meta.instance_id=beta:<instance>`;
- `app_meta.schema_version=<current worker schema>`.

It also checks D1 migration count before exposure.

Existing complete pairs are reusable only when the existing D1 already proves the matching identity. An existing unmarked/wrong-instance D1 is never auto-claimed.

### 6. Worker/D1/R2 pairing and A2 R2 residual risk

The generated manifest and generated Worker config must agree on:

- Worker name;
- D1 name and resolved database ID;
- R2 bucket name;
- DB/MEDIA binding names;
- runtime instance identity.

A1 checks target D1 and target R2 existence using Wrangler control-plane reads and redeploys the Worker from the reviewed generated config.

Because A2 cannot read a stable R2 bucket identity at application runtime, the runbook requires a mandatory pre-exposure Cloudflare Worker binding comparison against the generated manifest. The operator must verify `DB` and `MEDIA` are the exact beta resources and record that evidence outside the repository without secrets.

### 7. Predictable rerun behavior

- D1 + R2 both absent: create the deterministic pair.
- D1 + R2 both present with matching D1 identity: reuse the same pair.
- only one half present: fail closed; do not auto-create the missing half.
- D1 identity missing/wrong: fail closed; do not rewrite it.
- deterministic Worker exists while D1/R2 are absent: fail closed rather than overwrite an orphan/unrelated Worker.
- unrelated resource names are ignored.

### 8. Lifecycle runbook

The runbook covers:

- prepare;
- dry-run review;
- apply;
- interactive secret configuration;
- verify;
- mandatory R2 binding check;
- explicit beta-only exposure;
- smoke;
- decommission.

Initial `apply` deploys a non-routed Worker. Public beta exposure is intentionally a separate operator action after identity/pairing verification and secret configuration.

Decommission order is:

1. Worker;
2. R2;
3. D1 only after R2 deletion succeeds.

If R2 deletion fails, D1 is retained for investigation.

- A2 runtime identity and D1 stored identity are explicitly connected by provisioning.
- Existing wrong/unmarked D1 resources fail closed rather than being claimed.
- Partial pairs and orphan Workers fail closed instead of being silently completed/overwritten.
- Production identifiers are rejected before mutation.
- Secret values are kept out of generated review artifacts and repository history.
- The remaining R2-only binding risk is made an explicit mandatory operator check before exposure.
