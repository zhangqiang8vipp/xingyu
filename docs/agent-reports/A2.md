## Implemented

1. **Explicit runtime instance identity**
   - `APP_ENV` must explicitly be one of `development`, `beta`, or `production`; unknown values no longer silently collapse to production.
   - `INSTANCE_ID` is mandatory.
   - `INSTANCE_ID` must be environment-namespaced as `<APP_ENV>:<instance>`, for example `beta:alice` or `production:primary`. This makes beta and production identities structurally distinct.

2. **Persisted D1 identity**
   - D1 uses the existing `app_meta` table with a new required `instance_id` marker.
   - Every validated database must have both `app_environment` and `instance_id` matching the runtime identity exactly.
   - A truly empty `legacy-bootstrap` database persists both markers during its first initialization.
   - A non-empty unmarked database is never auto-claimed.

3. **Fail-closed mismatch handling**
   - `migration-only` mode requires an existing matching `instance_id`; missing or mismatched identity fails before schema/content access proceeds.
   - An Alice runtime bound to Bob's D1 fails without rewriting Bob's marker.
   - A beta runtime bound to a production D1 fails without rewriting production markers.
   - Missing runtime identity and missing persisted identity both fail closed.

4. **Guard before resource workflows**
   - Worker `fetch` now calls the identity/database gate before path-specific application logic.
   - Scheduled attachment cleanup / view pruning / health work calls the same gate first and returns without executing the resource workflow when identity validation fails.

## Deliberately not implemented

- No shared multi-tenant database conversion.
- No `tenant_id`, Workspace/Organization abstraction, membership expansion, or cross-user routing.
- No request-time repair/backfill of instance identity on an existing database. That would let a wrongly bound runtime claim a database and defeat the guard.
- No production or beta resource deployment/mutation.
- No R2 sentinel write/read mechanism in this sprint; see residual risk below.

## Security / isolation impact

- Wrong D1 bindings now fail closed at instance granularity rather than only at development-vs-production granularity.
- `APP_ENV=beta` is a first-class identity instead of being treated as production.
- Environment-prefixed `INSTANCE_ID` prevents the same configured identifier from being reused unchanged across beta and production.
- The gate runs before HTTP business paths and scheduled cleanup, reducing the chance that a wrongly bound instance reads, writes, or performs cleanup against another instance's D1-backed state.
- Existing/non-empty databases with no instance identity fail instead of being silently adopted.

## Schema / migration impact

- No table/column/index DDL change.
- Application schema version remains `19`.
- There is a new **required data marker** in the existing `app_meta` table: `key='instance_id'`.
- For `migration-only` beta/production instances, provisioning must set a verified per-instance marker before exposing the Worker, and must inject the matching runtime `INSTANCE_ID`.
- Existing databases will intentionally fail closed until that marker is explicitly provisioned. A2 does not backfill it from request traffic.

## R2 residual risk

The current R2 binding available to application code does not expose a stable bucket identity that can be compared with `INSTANCE_ID`. A2 therefore cannot enforce an equivalent D1-style identity check for R2 without introducing a separate sentinel/object protocol and resource writes.

The D1 guard runs before business/resource workflows, so a generally wrong instance binding is stopped early. However, **a correct D1 binding combined with an independently misbound R2 bucket remains a residual isolation risk**. A1 provisioning and A5/A6 acceptance must verify the D1 + R2 resource pair for each instance out of band. This sprint deliberately documents rather than hides that limitation.

## Known risks / integration requirements

- A1/A6 must ensure every beta instance has matching runtime `INSTANCE_ID=beta:<instance>` and D1 `app_meta.instance_id` before the first request.
- Production must receive its own `production:<instance>` runtime value and matching D1 marker before deploying code containing this guard; otherwise failure is expected and intentional.
- The new Wrangler integration contracts have not been executed in this tool environment; full `npm run ci` is a hard integration gate for A6.
- R2-only misbinding is not detectable by this application-level identity contract and must remain in the beta safety checklist.
