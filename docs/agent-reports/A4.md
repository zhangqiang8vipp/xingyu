## CEO review defect

The previous A4 implementation could produce false-positive activation:

1. `knowledgeCount` counted every post, including public/root blog posts.
2. Root `create_draft` with `spaceId=null` counted as a private activation write.
3. Root draft `update_post` with `spaceId=null` counted as private.
4. The previous unit test explicitly asserted those incorrect behaviors.

That contradicted the beta product gate: real private knowledge must live in a Knowledge Space, and the Agent's activation write must happen inside that private knowledge boundary.

## Corrected semantics

Activation now follows these rules:

1. **Knowledge prerequisite** means at least one post with `space_id IS NOT NULL`.
2. Public/root blog posts with `space_id IS NULL` never satisfy the knowledge prerequisite, regardless of `draft` or `published` status.
3. A qualifying Activation write must:
   - be `create_draft` or `update_post`; and
   - target a post with `spaceId != null`.
4. Root `create_draft` is not an Activation write.
5. Root `update_post` is not an Activation write.
6. Knowledge Space create/update qualifies independently of draft/published status because Knowledge Space membership is the private boundary.
7. `connected-only` remains distinct from `activated`.

## Code changes

### `site/db/activation.ts`

- Knowledge count changed from all posts to:

```ts
db.select({ value: sql<number>`count(*)` }).from(posts)
  .where(isNotNull(posts.spaceId))
```

- Activation activity lookup now also fails closed on root content:

```ts
.where(and(
  inArray(mcpActivity.action, ["create_draft", "update_post"]),
  isNotNull(posts.spaceId),
))
```

- Draft/published status is no longer used as a proxy for privacy.

### `site/domain/admin/activation.ts`

- Added `isKnowledgeSpacePost()`.
- `isPrivateActivationWrite()` now qualifies only `create_draft` / `update_post` with non-null `spaceId`.
- Removed `afterStatus` from the privacy decision.
- User-facing action labels now say “知识空间草稿 / 知识空间内容”.

### `site/features/admin/AdminIntegrationsPanel.tsx`

The primary activation UI now matches the corrected model:

- prerequisite: “知识空间里有真实知识”;
- root/public blog content is explicitly stated not to count;
- connected-only next step explicitly asks the Agent to save into **知识空间**;
- proof is labeled “最近一次知识空间写入”;
- copy no longer implies that any draft/private-looking root article can activate the user.

No publish/destructive boundary was changed.
