# 附件补偿队列独立发布：schema 14 → 15

**范围**：只发布迁移 0013 和附件失败持久队列。0014 的未绑定过期扫描及 PR-04 以后功能不在本次范围。生产绑定必须仍为 Green `xingyu-production-v2` 和现有 R2。

## 已确认的验收场景

| 前置 | 操作 | 预期与可观察结果 |
| --- | --- | --- |
| Green 为 schema 14，已暂停后台、MCP 和浏览计数写入 | 从届时最新 Green 独立导出两份 17 张业务表，并核对表行数、内容摘要、文章与附件及 R2 键集 | 两份导出哈希一致；记录当前数据基线。旧 Blue 与 2026-09-29 快照不得替代本次数据 |
| 最新快照已验证 | 在隔离副本应用 0013；生产只应用 0013，核对 `d1_migrations=14`、队列表与唯一索引后写 `schema_version=15` | 原有行与关系审计不变；队列初始为空；不运行 0014–0016 |
| schema 15 校验通过 | 发布此隔离候选并烟测公开页、匿名后台、管理员附件接口 | 公开页可读、匿名不能读队列，管理员可列出队列；其他用户代码和绑定未被替换 |
| 隔离环境使用故障 R2 绑定 | 分别令上传回滚和已提交的附件删除清理失败 | 按对象键入队，重复故障累计 attempts；生产 R2 不做故障注入 |
| 队列中对象仍存在 | 管理员尝试 resolve；按精确键移除隔离 R2 对象后重试 | 存在时 409，不存在时成功；任何路径不自动删除生产对象 |

## 执行边界

1. 记录现役 Worker 版本和 Green 数据库 ID。冻结所有写入后做只读基线；任何导出或核对不一致，停止迁移并解除冻结。
2. 把最新导出保存在仓库外受限目录，验证两份哈希及逐表行数与内容；在隔离库先应用唯一的 0013 并验证恢复。本站含 FTS5 虚拟表，Wrangler 整库导出会失败；按生产只读盘点后的 17 张普通业务表在同一条 `d1 export` 命令中使用重复的 `--table` 参数，并排除 FTS 影子表。不得复用旧快照充当最新基线。
3. 确认生产迁移目录只有 0000–0013 后执行 `npx wrangler d1 migrations apply DB --remote --config wrangler.production.jsonc`。核对迁移数 14、`attachment_cleanup_queue` 表、`attachment_cleanup_queue_object_key_uidx` 唯一索引、现有数据和 13 项关系审计。
4. 仅结构和数据均通过才把 `app_meta.schema_version` 从 14 写为 15，并部署本候选。若迁移已应用但尚未写版本标记，可保留现役 schema 14 Worker 并调查；写版本标记后旧 Worker 的启动校验会拒绝 15，不能直接切回。
5. 烟测后解除写入冻结。保存新 Worker 版本、迁移核验结果、最新备份位置和时间。若部署后出错，优先前向修复；任何数据恢复必须基于事故时最新 Green，再隔离验证。

**禁止**：把本地 schema 18 分支部署到 schema 15；直接切回旧 Blue；手工改 `d1_migrations`；把导出文件放进仓库；为了验收在生产制造 R2 删除失败。
