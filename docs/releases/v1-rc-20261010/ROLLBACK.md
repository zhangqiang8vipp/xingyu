# 回滚

## 可以整库回滚的窗口

同时满足时，可以用迁移前备份恢复 D1，并把 Worker 切回迁移前的版本：

- 还没有新的注册用户、邀请、组织、团队、空间 ACL 或工作区文章写入。
- 备份的 SHA-256 和行数清单还在。
- 恢复演练曾经在隔离库成功过。

恢复后核对 `schema_version`、`instance_id`、文章行数和 `public_id` 清单，再把流量切回旧 Worker。旧 Worker 不能指向已经标成 Schema 24 的库。

## 必须先冻结、不能覆盖备份的窗口

已经有新用户或协作数据时，用迁移前备份覆盖会丢掉这些数据。此时：

1. 关闭 `REGISTRATION_ENABLED`。
2. 停止邀请、组织管理和 MCP 新授权。
3. 再导出一份当前库。
4. 用向前修复处理缺陷。不要部署 Schema 19 的 Worker 去读 Schema 24 的库。

## R2

这次迁移不搬迁对象。回滚 D1 时不要删除 R2 里迁移前就存在的对象。迁移之后新上传的对象要按当时的附件记录决定是否保留，不能靠清空桶来“回滚”。

## Worker

保留迁移前的 Worker 版本号。回滚是把流量切回该版本，而不是在新代码上改数据库标记。
